# Кофе, котята и ты — GitHub Pages + Supabase

Игра основана на исходном HTML-файле и сохраняет финальный выбор в Supabase. `admin.html` — закрытая панель с входом по Supabase Auth.

## 1. Создай проект Supabase
1. Открой https://supabase.com/ и создай проект.
2. В проекте открой **SQL Editor → New query**, вставь содержимое `supabase/setup.sql` и нажми **Run**.
3. Открой **Authentication → Sign In / Providers** (название раздела может немного отличаться) и отключи публичную регистрацию / Sign-ups.
4. В **Authentication → Users** создай пользователя администратора вручную с email и сильным паролем. Сохрани пароль в менеджере паролей.
5. В **Project Settings → API** найди Project URL и publishable/anon key.

## 2. Заполни конфигурацию
Открой `config.js` и замени значения:
- `supabaseUrl` — URL проекта, например `https://abcdefgh.supabase.co`;
- `supabaseAnonKey` — publishable key (или legacy anon key).

В `config.js` нельзя помещать `service_role`, secret key или пароль администратора. URL и publishable/anon key видны посетителям; безопасность данных обеспечивают grants и RLS.

## 3. Опубликуй на GitHub Pages
1. Создай на GitHub новый **Public repository**, например `kofe-kotyata-i-ty`.
2. Загрузи в корень репозитория `index.html`, `admin.html`, `config.js`, `.nojekyll`, а также папку `supabase` (для документации).
3. Открой **Settings → Pages**.
4. В **Build and deployment → Source** выбери **Deploy from a branch**, ветку `main` и папку `/ (root)`, затем **Save**.
5. Дождись публикации. Ссылка будет вида `https://ТВОЙ-ЛОГИН.github.io/kofe-kotyata-i-ty/`.
6. Панель администратора: `https://ТВОЙ-ЛОГИН.github.io/kofe-kotyata-i-ty/admin.html`.

## 4. Проверь перед отправкой
1. Открой игру по публичной ссылке и пройди все шесть сцен до финала.
2. Убедись, что в финале отображается сообщение об успешном сохранении.
3. Открой `admin.html`, войди email/паролем созданного администратора и проверь, что появился ответ.
4. Выйди из панели. Без входа результаты не должны отображаться.
5. Проверь, что игра честно сообщает посетительнице, что ответ сохранится и автор увидит его.

## Как устроена защита
- GitHub Pages — только статический хостинг; базу обслуживает Supabase.
- Публичная роль `anon` имеет право только вставить ответ, но не читать таблицу.
- Роль `authenticated` имеет право читать ответы; поэтому отключи регистрацию и создай только свой администраторский аккаунт.
- Никогда не выдавай `service_role`/secret key браузеру.

## Если не работает
- Сообщение «Сохранение ещё не настроено» — проверь `config.js` и обнови опубликованный сайт.
- Ошибка сохранения — проверь, что SQL выполнен полностью, URL/ключ правильные и имя таблицы `game_answers` совпадает.
- Не удаётся войти — проверь email/пароль и что аккаунт администратора создан в Supabase Auth.
- После изменения файлов подожди завершения Pages deployment и обнови страницу без кеша.
